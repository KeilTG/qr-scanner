# ФК — QR

Веб-приложение для начисления баллов участникам мастер-классов по QR-кодам.

Участник получает личный QR-код на телефон. На каждой площадке (мастер-классе) специалист сканирует
код, при первом сканировании вписывает ФИО и учебное заведение участника, а затем может начислить ему 1 балл.
Администраторы управляют площадками и сотрудниками, видят статистику и рейтинг участников.

**Стек:** Python 3.12 · FastAPI · PostgreSQL 16 · asyncpg · чистый HTML/CSS/JS (без сборки) · jsQR · Docker Compose.

## Роли и права

| Роль | Что может |
|---|---|
| **Участник** | Показывает свой QR-код. Видит, сколько баллов ему начислено и какие площадки он посетил. Входить не нужно: код выдаётся одной кнопкой. |
| **Специалист МК** | Привязан к **одной** площадке (название МК, этаж, кабинет). Сканирует QR-код участника и вписывает его данные: ФИО и колледж/школу. После сканирования участник попадает в список посетивших МК, и специалист может начислить ему **1 балл**. |
| **Администратор площадки** | Привязан к одной площадке. Создаёт специалистов МК своей площадки. Может сканировать QR-коды и начислять баллы. Видит всех специалистов площадки: сколько баллов и каким участникам начислил каждый. Видит участников площадки и баллы, выданные от её лица. Может отменить ошибочно начисленный балл, сбросить пароль специалисту, отключить его. |
| **Администратор колледжа** | Всё, что умеет администратор площадки, но **на любой площадке своего колледжа**. Дополнительно: создаёт площадки (название МК, этаж, кабинет), создаёт администраторов площадок и специалистов. Видит все площадки, всех администраторов и специалистов колледжа, все баллы, общую статистику и **рейтинг участников** по набранным баллам. |
| **Администратор системы** | Может всё и видит всё: создаёт колледжи и их администраторов, управляет всеми площадками и пользователями всех колледжей, видит общий рейтинг или рейтинг по выбранному колледжу. |

### Правила начисления баллов

- На **одной площадке** участник получает **не больше 1 балла**. Повторное сканирование не создаёт дубль: приложение покажет «Уже отмечен ранее».
- Если на площадке несколько специалистов, балл засчитывается тому, кто его начислил.
- Баллы на разных площадках суммируются. Итог участника = количество площадок, где ему начислили балл.
- Начислить балл можно, только когда у участника заполнено ФИО.
- Отменить балл может администратор площадки, колледжа или системы. Специалист отменить балл не может.

### Матрица прав

| Действие | Специалист | Админ площадки | Админ колледжа | Админ системы |
|---|:-:|:-:|:-:|:-:|
| Сканировать QR, вписывать ФИО/учебное заведение | своя площадка | своя площадка | любая площадка колледжа | любая |
| Начислить 1 балл | ✓ | ✓ | ✓ | ✓ |
| Отменить балл | — | ✓ | ✓ | ✓ |
| Видеть список посетивших площадку | ✓ | ✓ | ✓ | ✓ |
| Видеть специалистов и их баллы | — | своя площадка | весь колледж | всё |
| Создавать специалистов МК | — | на своей площадке | в колледже | везде |
| Создавать админов площадок | — | — | в колледже | везде |
| Создавать / изменять площадки | — | — | в колледже | везде |
| Рейтинг участников и статистика | — | — | по колледжу | общий и по колледжам |
| Создавать колледжи и их админов | — | — | — | ✓ |

Права проверяются **на сервере** в каждом запросе. Интерфейс просто не показывает недоступные кнопки.

## Быстрый старт (Docker)

Нужен установленный и запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
git clone https://github.com/KeilTG/qr-scanner.git
cd qr-scanner
cp .env.example .env          # по желанию: поменяйте пароли и укажите HOST_IP
docker compose up -d --build
```

Поднимутся два контейнера:

| Контейнер | Что это | Порт |
|---|---|---|
| `fk-db` | PostgreSQL 16, данные лежат в томе `pgdata` | `5433` на компьютере → `5432` в контейнере |
| `qr-scanner` | приложение (FastAPI + интерфейс) | `8443` (HTTPS) |

Откройте **https://localhost:8443**. Браузер предупредит о сертификате: нажмите «Дополнительно» → «Перейти на сайт» ([почему так](#доступ-с-телефона-и-https)).

### Пароль администратора системы

При первом запуске создаётся администратор системы:
- логин берётся из `ADMIN_LOGIN` (по умолчанию `admin`);
- пароль берётся из `ADMIN_PASSWORD`. Если переменная пустая, пароль генерируется случайно и **выводится в лог**:

```bash
docker compose logs qr-scanner | grep "администратор"
# Создан администратор системы: логин «admin», пароль «JQKzCy0pTsVa»
```

После входа смените пароль кнопкой **«Пароль»** в шапке.

### Полезные команды

| Команда | Что делает |
|---|---|
| `docker compose up -d --build` | собрать и запустить (после изменений в коде тоже) |
| `docker compose logs -f qr-scanner` | логи приложения и адреса для подключения |
| `docker compose ps` | состояние контейнеров |
| `docker compose stop` | остановить |
| `docker compose down` | остановить и удалить контейнеры (**данные БД сохранятся**) |
| `docker compose down -v` | ⚠️ удалить контейнеры **и все данные** (БД и сертификат) |
| `docker compose exec db psql -U fk -d fk` | консоль PostgreSQL |

## Первый вход и настройка мероприятия

Типичный порядок действий:

1. **Администратор системы** входит под `admin`.
2. Вкладка **«Колледжи»** → создаёт колледж (например, «Колледж связи №54»).
3. Там же создаёт **администратора колледжа**: ФИО, логин, пароль.
4. **Администратор колледжа** входит под своим логином.
5. Вкладка **«Площадки»** → создаёт площадки: название МК, этаж, кабинет.
6. Нажимает на площадку → блок «Добавить сотрудника площадки» → создаёт **администратора площадки** и/или **специалистов МК**. Это же можно сделать на вкладке **«Пользователи»**.
7. **Администратор площадки** при желании сам добавляет специалистов своей площадки (вкладка **«Специалисты»**).
8. Логины и пароли раздаются сотрудникам. Они входят с телефонов, и у каждого сразу открывается сканер своей площадки.
9. **Участники** открывают сайт на своих телефонах и нажимают **«Получить мой QR-код»**.

> Логин: латиница, цифры, `.`, `-`, `_`, от 3 символов. Пароль: от 6 символов.

## Как пользоваться: по ролям

### Участник

1. Открыть сайт → **«Получить мой QR-код»**.
2. На экране появятся QR-код и код вида `FK-ABCD2345` (его можно продиктовать, если камера не читает QR).
3. Показать QR специалисту на мастер-классе.
4. На этом же экране видно:
   - **сколько баллов начислено**;
   - **какие площадки посещены** и где начислен балл.
   Экран обновляется сам каждые 8 секунд.
5. **Важно:** код хранится в браузере телефона. Нажмите **«Скопировать ссылку»** и сохраните её (например, отправьте себе в мессенджер). По ссылке код откроется на любом устройстве или после очистки браузера.

### Специалист МК

Вкладка **«Сканер»**. Название площадки показано вверху.

1. **«Сканировать QR-код»** → навести камеру на код участника. Есть запасные варианты: **«Из картинки»** (скриншот или фото кода) и **«Ввести код»** вручную.
2. Появится карточка участника:
   - **«Новый посетитель»**: участник отмечен на площадке впервые;
   - **«Уже отмечен ранее»**: повторное сканирование, дубля не будет.
3. Если участник сканируется впервые и данных о нём нет, впишите **ФИО** и **колледж / школу** → «Сохранить данные». Данные вписываются один раз и видны на всех площадках. Исправить их можно кнопкой «Изменить данные».
4. **«Начислить 1 балл»**.
5. **«Сканировать следующего»**.

Справа (на телефоне — ниже) находится **список посетивших площадку** с поиском. Балл можно начислить и отсюда, кнопкой «+1 балл». Список обновляется каждые 15 секунд, поэтому видно и то, что отметили коллеги.

### Администратор площадки

- **«Сканер»**: то же, что у специалиста.
- **«Специалисты»**:
  - создать специалиста МК (ФИО, логин, пароль);
  - таблица сотрудников площадки и **сколько баллов начислил каждый**. Под ФИО есть раскрывающийся список «Кому начислил»: участники, колледж/школа, время;
  - «Сбросить пароль», «Отключить / Включить».
- **«Участники»**: все, кто посетил площадку: ФИО, учебное заведение, код, когда и кем отмечен, начислен ли балл и кем. Вверху показано общее число **баллов, выданных от площадки**. Можно начислить или **отменить** балл и **скачать CSV** (открывается в Excel).

### Администратор колледжа

- **«Обзор»**: число площадок, админов площадок, специалистов, участников, посещений и выданных баллов; топ-10 участников; список площадок с баллами.
- **«Сканер»**: можно сканировать **на любой площадке колледжа**. Площадка выбирается из списка, выбор запоминается.
- **«Площадки»**: создание площадки (название МК, этаж, кабинет) и таблица всех площадок с числом админов, специалистов, посещений и баллов. Если нажать на площадку, откроется её страница:
  - редактирование названия, этажа и кабинета, удаление (только если на площадке ещё не было посещений);
  - создание **администратора площадки** или **специалиста МК**;
  - сотрудники и их баллы (как у админа площадки);
  - участники площадки и баллы.
- **«Пользователи»**: все админы площадок и специалисты колледжа: создание, фильтр по роли, сброс пароля, отключение.
- **«Рейтинг»**: участники, отсортированные по **максимуму набранных баллов**. При равенстве баллов выше тот, кто набрал их раньше. Одинаковое число баллов = одинаковое место. Есть поиск и выгрузка в CSV.

### Администратор системы

Всё то же, что у администратора колледжа, но по всем колледжам, плюс:
- **«Колледжи»**: создание и переименование колледжей, создание **администраторов колледжей**;
- на вкладках «Обзор», «Площадки», «Пользователи», «Рейтинг» есть фильтр **«Колледж»** (или «Все колледжи»);
- может создавать пользователей любой роли, в том числе других администраторов системы.

## Настройки (.env)

Файл `.env` лежит рядом с `docker-compose.yml` (шаблон: `.env.example`). Он не попадает в git.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HOST_IP` | — | IP компьютера в локальной сети, для доступа с телефонов (см. ниже) |
| `POSTGRES_DB` | `fk` | имя базы |
| `POSTGRES_USER` | `fk` | пользователь БД |
| `POSTGRES_PASSWORD` | `fk_password` | пароль БД. **Поменяйте** перед реальным использованием |
| `POSTGRES_PORT` | `5433` | порт БД на компьютере (для DBeaver/pgAdmin). 5433 выбран, чтобы не конфликтовать с локальным PostgreSQL |
| `ADMIN_LOGIN` | `admin` | логин первого администратора системы |
| `ADMIN_PASSWORD` | случайный | пароль первого администратора; если пусто, генерируется и печатается в лог |

Переменные самого приложения (передаются в контейнер через compose):

| Переменная | Описание |
|---|---|
| `DATABASE_URL` | строка подключения, например `postgresql://fk:fk_password@db:5432/fk` |
| `PORT` | порт HTTPS-сервера, по умолчанию `8443` |
| `CERT_DIR` | где хранить сертификат, в Docker это `/certs` |
| `EXTRA_IPS` | IP-адреса через запятую для сертификата (из `HOST_IP`) |

> `POSTGRES_PASSWORD` применяется только при **первом** создании базы. Если база уже создана,
> смена переменной ничего не даст: пароль меняется через `ALTER USER fk PASSWORD '...'` или пересозданием тома.

## Доступ с телефона и HTTPS

Браузеры дают доступ к камере только на `localhost` или по **HTTPS**, поэтому сервер всегда работает по HTTPS.
При первом запуске `serve.py` создаёт **самоподписанный сертификат** (`openssl`) и сохраняет его в томе `certs`.

Чтобы зайти с телефона:
1. Телефон и компьютер должны быть в одной сети Wi-Fi.
2. Узнайте IP компьютера: `ipconfig` → «IPv4-адрес» (например, `192.168.1.10`).
3. Пропишите его в `.env`: `HOST_IP=192.168.1.10`.
4. Пересоздайте сертификат, чтобы в нём был этот IP:
   ```bash
   docker compose down
   docker volume rm qr_scanner_certs
   docker compose up -d
   ```
5. Откройте на телефоне `https://192.168.1.10:8443` и подтвердите переход («Дополнительно» → «Перейти на сайт»).

Если сканер не открывает камеру, проверьте, что адрес начинается с `https://` и что браузеру разрешён доступ к камере.

> Если брандмауэр Windows спросит разрешение для Docker, разрешите доступ в частных сетях.

## База данных

PostgreSQL 16 в контейнере `fk-db`, данные в docker-томе `pgdata` (переживают перезапуск и `docker compose down`).
Схема создаётся автоматически при старте приложения из `app/schema.sql` (все таблицы через `IF NOT EXISTS`).

### Схема

```
colleges ─┬─< sites ─┬─< visits >── participants
          │          │      │  │
          │          └─< users (site_admin, specialist)
          └─< users (college_admin)          │  │
                                scanned_by ──┘  └── awarded_by → users
users ─< sessions
```

| Таблица | Назначение | Основные поля |
|---|---|---|
| `colleges` | колледжи-организаторы | `name` (уникальное) |
| `sites` | площадки (мастер-классы) | `college_id`, `name`, `floor`, `room` |
| `users` | сотрудники всех ролей | `login` (уникальный), `password_hash`, `full_name`, `role`, `college_id`, `site_id`, `is_active` |
| `participants` | участники | `code` (в QR, публичный), `secret` (личный токен), `full_name`, `institution` |
| `visits` | посещение площадки участником | `site_id`, `participant_id`, `scanned_by`, `scanned_at`, `points` (0/1), `awarded_by`, `awarded_at`; **уникальность (site_id, participant_id)** |
| `sessions` | сессии входа сотрудников | `token`, `user_id`, `expires_at` (30 дней) |

Ограничения на уровне БД:
- `role` может быть только `system_admin | college_admin | site_admin | specialist`;
- у админа площадки и специалиста **обязательно** указан `site_id`, у остальных ролей он пустой;
- у всех, кроме администратора системы, обязательно указан `college_id`;
- `points` может быть только 0 или 1, а пара (площадка, участник) уникальна. Начислить два балла на одной площадке невозможно даже при одновременных запросах.

### Подключение к БД с компьютера

DBeaver / pgAdmin / DataGrip: хост `localhost`, порт `5433`, база `fk`, пользователь `fk`, пароль из `POSTGRES_PASSWORD`.

Полезные запросы:

```sql
-- рейтинг участников
SELECT p.full_name, p.institution, sum(v.points) AS points, count(*) AS sites
FROM participants p JOIN visits v ON v.participant_id = p.id
GROUP BY p.id ORDER BY points DESC;

-- сколько баллов начислил каждый специалист
SELECT u.full_name, s.name AS site, count(*) AS points
FROM visits v JOIN users u ON u.id = v.awarded_by JOIN sites s ON s.id = v.site_id
WHERE v.points = 1 GROUP BY u.id, s.name ORDER BY points DESC;
```

### Забыли пароль администратора системы

```bash
docker compose exec db psql -U fk -d fk -c "UPDATE users SET is_active = false WHERE role = 'system_admin';"
docker compose restart qr-scanner
docker compose logs qr-scanner | grep "администратор"
```
Если активного администратора системы нет, приложение при старте восстанавливает учётную запись `ADMIN_LOGIN` с новым паролем: из `ADMIN_PASSWORD` или случайным, напечатанным в лог.

## Запуск без Docker

Нужны Python 3.10+, `openssl` в `PATH` (в Windows он идёт с Git for Windows) и запущенный PostgreSQL.

```bash
pip install -r requirements.txt
# создать БД: CREATE USER fk PASSWORD 'fk_password'; CREATE DATABASE fk OWNER fk;
set DATABASE_URL=postgresql://fk:fk_password@localhost:5432/fk     # Windows (cmd)
export DATABASE_URL=postgresql://fk:fk_password@localhost:5432/fk  # Linux/macOS
python serve.py
```

Можно поднять в Docker только базу: `docker compose up -d db`. Тогда `DATABASE_URL=postgresql://fk:fk_password@localhost:5433/fk`.

## Как это работает

```
 Телефон участника                     Сервер (FastAPI, HTTPS :8443)              PostgreSQL
 ┌──────────────────┐  POST /participant/register  ┌────────────────────────┐   ┌──────────┐
 │ «Получить QR»    ├─────────────────────────────►│ code=FK-XXXXXXXX       ├──►│participants│
 │ QR (SVG с сервера)◄──── GET /participant/qr.svg ─┤ secret → localStorage  │   └──────────┘
 └──────────────────┘                              │                        │
 Телефон специалиста                               │                        │
 ┌──────────────────┐                              │ проверка роли и        │   ┌──────────┐
 │ камера → jsQR()  ├──── POST /api/scan {code} ──►│ площадки, INSERT visit ├──►│ visits   │
 │ ФИО, колледж     ├──── PATCH /participants/{id}►│ ON CONFLICT DO NOTHING │   │ (1 на    │
 │ «+1 балл»        ├──── POST /visits/{id}/award ►│ UPDATE … WHERE points=0├──►│ площадку)│
 └──────────────────┘                              └────────────────────────┘   └──────────┘
```

- **QR-код участника** содержит только публичный код `FK-XXXXXXXX`. Личный `secret` хранится в браузере участника и нужен, чтобы смотреть свои баллы. Зная только код, чужие баллы не посмотреть.
- **Распознавание QR** происходит на устройстве специалиста (jsQR). На сервер уходит только текст кода.
- **QR-картинку** рисует сервер (библиотека `segno`, SVG), поэтому на телефоне участника ничего не вычисляется.
- **Сотрудники** входят по логину и паролю. Сервер ставит httpOnly-cookie с токеном сессии (30 дней). Пароли хранятся как PBKDF2-SHA256 (200 000 итераций, соль).
- **Права** проверяются функциями `can_access_site`, `site_scope` и `can_manage` в `app/main.py`.
- **Начисление балла** выполняется одним запросом `UPDATE visits SET points = 1 … WHERE points = 0`. Двойное нажатие или два специалиста одновременно не дадут второй балл.

## API

Все запросы и ответы в JSON. Сотрудникам нужна cookie `fk_session` (ставится при входе), участнику нужен заголовок `X-Participant-Token`.
Интерактивная документация FastAPI доступна по адресу **https://localhost:8443/docs**.

| Метод и путь | Кто | Описание |
|---|---|---|
| `POST /api/auth/login` | все сотрудники | `{login, password}` → ставит cookie |
| `POST /api/auth/logout` | | выход |
| `GET /api/me` | сотрудник | текущий пользователь, роль, колледж, площадка |
| `POST /api/me/password` | сотрудник | `{old_password, new_password}` |
| `POST /api/participant/register` | любой | новый участник → `{code, secret}` |
| `GET /api/participant/me` | участник | баллы и посещённые площадки |
| `GET /api/participant/qr.svg?t=<secret>` | участник | картинка QR-кода |
| `POST /api/scan` | сотрудник | `{code, site_id?}`: отметить участника на площадке |
| `PATCH /api/participants/{id}` | сотрудник | `{full_name, institution}` |
| `GET /api/sites/{id}/visits` | сотрудник площадки | список посетивших |
| `POST /api/visits/{id}/award` | сотрудник площадки | начислить 1 балл |
| `DELETE /api/visits/{id}/award` | админы | отменить балл |
| `GET /api/sites/{id}/report` | админы | сотрудники площадки с баллами + посещения |
| `GET/POST /api/sites`, `GET/PATCH/DELETE /api/sites/{id}` | просмотр: все в своей области; изменение: админ колледжа и системы | площадки |
| `GET/POST /api/users`, `PATCH /api/users/{id}` | админы | пользователи (создание, сброс пароля, отключение, перенос на другую площадку) |
| `GET/POST /api/colleges`, `PATCH /api/colleges/{id}` | просмотр: все; изменение: админ системы | колледжи |
| `GET /api/rating?college_id=` | админ колледжа и системы | рейтинг участников |
| `GET /api/stats?college_id=` | админ колледжа и системы | сводные цифры |
| `GET /api/health` | любой | проверка работы приложения и БД |

Ошибки возвращаются как `{"detail": "текст на русском"}` с кодами 400/401/403/404/409/422.

## Безопасность

- **Смените** `POSTGRES_PASSWORD` и пароль `admin` перед реальным мероприятием.
- Приватный ключ сертификата (`*.pem`) и `.env` исключены из git.
- Порт БД `5433` открыт на компьютере для удобства. Если он не нужен, удалите блок `ports` у сервиса `db` в `docker-compose.yml`.
- Отключённый пользователь сразу теряет все сессии. Смена пароля сбрасывает сессии на других устройствах.
- Самоподписанный сертификат подходит для локальной сети. Для публикации в интернете поставьте перед приложением обратный прокси с настоящим сертификатом (Caddy, nginx + Let's Encrypt).

## Резервное копирование

```bash
# сохранить базу в файл
docker compose exec -T db pg_dump -U fk fk > backup_$(date +%F).sql

# восстановить из файла (в пустую базу)
docker compose exec -T db psql -U fk -d fk < backup_2026-10-15.sql
```

В Windows PowerShell:
```powershell
docker compose exec -T db pg_dump -U fk fk | Out-File -Encoding utf8 backup.sql
Get-Content backup.sql | docker compose exec -T db psql -U fk -d fk
```

## Частые вопросы и проблемы

**`Bind for 0.0.0.0:5433 failed: port is already allocated`**
Порт занят. Укажите другой в `.env`: `POSTGRES_PORT=5434`.

**Сборка падает с `Read timed out` при `pip install`**
Медленный интернет до PyPI. Повторите `docker compose up -d --build`: в Dockerfile уже настроены увеличенный таймаут и повторы.

**На телефоне «Нет доступа к камере»**
Откройте сайт по `https://`, разрешите камеру в настройках браузера. На iPhone используйте Safari.

**Участник потерял QR-код (очистил браузер, сменил телефон)**
Если он сохранил ссылку «Скопировать ссылку», достаточно её открыть. Если нет, он получает новый код, а специалисту придётся заново ввести данные. Баллы старого кода останутся на старом коде.

**Специалист отсканировал не на той площадке**
Специалист всегда работает на своей площадке, ошибиться он не может. Админ колледжа выбирает площадку в списке над сканером: проверьте выбор. Ошибочно выданный балл админ может отменить во вкладке «Участники» площадки.

**Как перевести специалиста на другую площадку?**
Через API: `PATCH /api/users/{id}` с `{"site_id": N}` (админ колледжа или системы). Либо создайте ему новую учётную запись на нужной площадке.

**Как удалить все данные и начать заново?**
`docker compose down -v && docker compose up -d`. ⚠️ Удалятся база и сертификат, будет создан новый администратор (пароль в логах).
